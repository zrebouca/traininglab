DART — Transfere ou Resolve?

Decisão Correta no Contato Complexo

DART não é uma saída — é um recurso específico. Acionar o DART sem necessidade dobra o AHT do contato e transfere o problema sem resolvê-lo. Saber quando acionar e quando resolver por conta própria é fundamental.

DART é o canal de escalação para casos que genuinamente exigem expertise fora do escopo do atendimento padrão. Não é uma saída para contatos difíceis. Antes de acionar, pergunte: "Eu consigo resolver isso com as ferramentas que tenho?" Se a resposta é sim, resolva. O DART é para quando a resposta é não.
O DUR (DART Usage Rate) mede a porcentagem de contatos em que o DART foi acionado. Um DUR alto indica que o CSA está dependendo do DART para resolver situações que poderia tratar diretamente. Além disso, contatos com DART têm AHT médio quase duas vezes maior (18,6 min vs 9,3 min sem DART), impactando diretamente a métrica individual.
Contatos que passam pelo DART desnecessariamente costumam ter CCX mais baixo: o cliente é transferido, precisa repetir o problema e aguarda mais tempo. Um CSA com DUR alto tende a ter BTB de "Eficiência" e "Prestatividade" elevados. Reduzir o DUR e resolver mais na primeira tentativa é a combinação mais eficaz para CCX.
Muitos CSAs acionam o DART em casos de: reembolso com prazo vencido, produto com defeito, reclamações de entrega e problemas com parceiros. A maioria desses casos tem fluxo de resolução direta disponível. Conhecer esses fluxos é o principal diferencial de um CSA com DUR baixo.
O SIC (Service Issue Code) deve ser preenchido no momento em que a demanda é identificada — não no final do contato. Transferir para o DART com SIC em branco invalida o registro do contato e prejudica os dados de qualidade do time. Sempre preencha o SIC antes de iniciar qualquer escalação.
